# Web building, parcel and address presentation alignment

Reference: current local iOS MapTheme.swift, MapLayerManager.swift and DiamondGeometryProvider.swift, inspected November 5, 2026. This records map presentation/state work, not an assertion of whole-app feature parity.

## Implemented

- Main canonical and GeoJSON building layers: 0.6 m side rounding with flat roofs, iOS depth settings, height clamp (5.2–14 m) and 0.5 display scale. Stored physical height sanitation remains separate; Niagara absolute elevations are still rejected as structure heights.
- Alternate BuildingLayers and OvertureMap renderers use the same height/base expressions and rounding.
- Address cylinders: 0.2 m rounded cap, iOS depth, source/feature-state height and base with 3 m minimum; address labels begin at zoom 17 and use viewport alignment.
- Building-mode labels are enabled. Canonical unit layers use smaller 0.12 m side rounding.
- Canonical and legacy parcel overlays use the iOS zoom-dependent selected/active fill, line opacity and widths. Legacy parcels insert below extrusions even when loaded late.
- Shared palette matches iOS light unvisited blue-grey, lead blue and green visited/delivered statuses. Selection on untouched canonical homes and address markers uses theme-aware slate, preserving visited status colours.
- Canonical parcel state includes primary_address_id. QR colouring disabled restores the underlying address status. Existing per-unit, deleted-address and style-replay behavior remains covered by tests.
- Legacy address rendering now receives the actual map theme and selected address from the campaign map.

## Validation

Passed: canonical tile state and lifecycle, campaign address overview/click/deletion, building height guards, parcel click resolution, provided Farm cycle status, townhouse unit identity, reconciliation rules, four parcel ownership tests, and Mapbox style validation/evaluation.

Chrome rendered a synthetic concave building, address cylinder and selected parcel with no map errors. Screenshot visually inspected for broken extrusion geometry. Reproduce using `npx tsx scripts/test-ios-map-presentation.ts` (Chrome and a configured local Mapbox token required). It uses no customer data and makes no database changes.

Focused lint: no errors. Existing hook-dependency warnings remain in MapBuildingsLayer and OvertureMap. The full repository TypeScript check is blocked by errors outside the changed map files (integrations, demo players, session typing, map-styles, and existing test typings).

## Verification limits

The browser fixture is not an authenticated live Farm/Campaign walkthrough or a side-by-side physical iPhone comparison. It does not establish full parity for condo unit-entry UI, townhome editing tools, reverse-geocoding workflows, native offline downloads, or every route/team/demo map renderer. Those broader workflows were not implemented by this change. No commit, push or deployment was performed.
