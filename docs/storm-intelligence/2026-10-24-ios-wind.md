Implemented in the shared `/mobile/storms` workbench hosted by the existing iOS `StormCampaignBrowser` WKWebView. The connected phone has WolfGrid 1.30 (17), bundle com.danielphillippe.FLYR. No Swift binary, signing, entitlements, database schema, provider subscription, or App Store submission changed.

Production release: `dpl_5TeCAe5bBTRXfGq3uTLYNUHYQvxu`, staged from `/tmp/wolfgrid-ios-wind-release`, promoted to wolfgrid.app. It contains nine scoped runtime source changes over the previous verified wind release. Close and reopen Storm Maps to receive the updated workbench.

## Changes

- Saved wind raster images receive the native session through Mapbox's request transform, including worker-driven image requests that do not pass through the page's fetch wrapper.
- Headers are limited to the exact same-origin wind map endpoint. The current native workspace replaces any workspace in a tile URL. No app credentials are added to Mapbox, Xweather/MapsGL, external origins or unrelated APIs; credentials never enter URLs.
- Reconnection reads the refreshed token and rebuilds the wind raster source while preserving the selected wind hour. Wind-image 401 responses show the native Reconnect notice. Slow basemap loading and style changes retry missing wind layers on idle.
- Phone controls have at least 44px input height and readable input text. The phone's “Select wind area on map” action closes the sheet; a completed selection or selection error opens the sheet again. Selected native wind details scroll into view. The closed map displays a wind-specific tap instruction.
- Native wind campaign actions support the existing address campaign/planning/provisioning flow and an explicit area campaign without home loading. Both return the resulting campaign ID through the existing native navigation callback. Australia and New Zealand retain area campaigns only.
